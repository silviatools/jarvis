# Telegram-ассистент Джарвис — описание для переноса в другой проект

Документ описывает, как устроен ИИ-ассистент в Telegram-боте Джарвиса: что он принимает на вход, что умеет, как хранит контекст и как это воспроизвести в другом проекте. Источник — код в этом репозитории (`tg_bot.py`, `jarvis.py`, `file_tools.py`, `tg_tools.py`, `tg_user.py`, `deck_*.py`, `study_skills.py`).

---

## 1. Суть в одном абзаце

Пользователь пишет боту в Telegram (текст, фото, файлы, голосовые, кружки, пересылки). Сервер превращает всё это в текст/картинки и отдаёт LLM (Claude или OpenAI на выбор) вместе с набором **инструментов** (tool use / function calling). Модель в цикле вызывает инструменты — читает и меняет данные проекта, шлёт в чат чеклисты, файлы, картинки, опросы, собирает презентации, читает личный Telegram — и в конце даёт короткий ответ. Ответ уходит в Telegram форматированным HTML. Контекст диалога живёт в памяти 10 минут.

## 2. Стек и зависимости

| Что | Чем |
|---|---|
| Сервер | Python, один процесс, потоки (без asyncio в основной части) |
| Telegram Bot API | `requests` напрямую (без библиотек), **long polling** `getUpdates` (timeout 25 с) |
| LLM | Anthropic Messages API **или** OpenAI Chat Completions — по выбору пользователя (набор ключей в настройках) |
| Расшифровка голосовых | OpenAI `gpt-4o-transcribe`, запасной `whisper-1` |
| Генерация картинок | OpenAI Images, модель `gpt-image-1` |
| Личный Telegram-аккаунт | Telethon (отдельный event loop в потоке) |
| Файлы | `python-docx`, `openpyxl`, `python-pptx`, `pypdf`, `xlrd`, `fpdf2` (PDF с кириллицей — шрифты в `assets/fonts`) |
| Превью презентаций | LibreOffice (Impress) + poppler на сервере |
| Погода | Open-Meteo (без ключа) |
| Хранилище | JSON-файлы в `DATA_DIR` (Volume на Railway) |

`requirements.txt`: `requests telethon segno python-docx openpyxl python-pptx pypdf xlrd fpdf2`.
Системные пакеты (`nixpacks.toml`): `libreoffice-impress poppler-utils fontconfig fonts-dejavu-core fonts-liberation fonts-crosextra-carlito`.

### Переменные окружения

| Переменная | Назначение |
|---|---|

Модели по умолчанию: Claude — `claude-sonnet-5`, OpenAI — `gpt-4o` (можно задать любую в настройках).

## 3. Поток обработки сообщения

```
getUpdates (long poll, один поток)
  ├─ callback_query → кнопки (чеклисты tcl:, быстрые ответы tqr:, диета и т.п.)
  └─ message
       ├─ новый чат → подписка + приветствие
       ├─ /new, /reset → сброс контекста
       ├─ "/команда" → не ассистенту
       └─ текст или медиа → отдельный поток _dispatch_user_message
              1. extract_attachments(): фото/файлы/голос/видео → текст + картинки
              2. reply на сообщение бота → restore_anchor() (вернуть контекст отчёта)
              3. handle_assistant_message() под chat_lock(chat_id)
                    - history_for(chat_id): история; сброс, если пауза > TTL
                    - sendChatAction typing
                    - новый диалог → название генерируется параллельно
                    - tool-use цикл (Claude или OpenAI)
                    - ответ → send_text() (HTML, нарезка) + подпись с названием диалога
```

Важные детали:
- Обработка каждого сообщения идёт **в отдельном потоке** — long poll не блокируется долгим tool-use циклом.
- Сообщения одного чата идут **строго по очереди** (`chat_lock`) — история не перемешивается при быстрой переписке.
- Состояние Telegram-offset хранится в файле подписчиков; профили (имя, username) обновляются на каждом сообщении.

## 4. Что ассистент понимает на входе

Все входящие превращаются в **текст** (и иногда картинки) для модели — отдельной логики «под каждый тип» в промпте не нужно.

| Вход | Что происходит |
|---|---|
| **Текст** | как есть |
| **Фото** | берётся самое большое; уходит модели картинкой («что на фото?» по умолчанию). Запоминается как «недавний файл» |
| **Документ-картинка** (jpeg/png/webp/gif) | как фото |
| **Документ-файл** | `file_tools.read_file` → текст вставляется в сообщение как `[Файл «имя»]\n…` (до 60 000 символов). Нечитаемый файл — пометка с причиной |
| **Голосовое / аудио / видеокружок / видео** | скачивается (до 20 МБ), расшифровывается OpenAI; в сообщение идёт `[Голосовое сообщение, 0:42 — расшифровка]\n…`. Нет ключа OpenAI или файл слишком большой — пометка «почему не получилось», и модель пересказывает её пользователю |
| **Пересланное** | префикс `[Переслано от Имя]` (или `[Пересланное сообщение]`) |
| **Подпись к медиа** | объединяется с содержимым вложения |
| **Ответ (Reply) на сообщение бота** | если у того сообщения есть «якорь» — возвращается контекст того отчёта, даже если прошла пауза |
| **Нажатие кнопки** | `reply` кнопки приходит ассистенту как обычное сообщение пользователя |

### Читаемые форматы файлов
txt, md, csv, tsv, json, xml, html, yaml, ini, log, srt, ics, код (py, js, ts, sql, sh, css, java, c/cpp/cs, toml, tex…), **docx**, **xlsx/xlsm/xls**, **pptx**, **pdf** (только с текстовым слоем, сканы не читаются), **rtf**, **odt/ods/odp**, **zip** (содержимое архива). Старые `.doc` / `.ppt` не читаются — ассистент просит пересохранить в docx/pptx. Кодировки: UTF-8, UTF-16, cp1251.

### Лимиты входа
- скачивание файла ботом — **20 МБ** (лимит Bot API `getFile`);
- аудио для расшифровки — до 20 МБ;
- текст файла для модели — 60 000 символов;
- последние 5 присланных файлов хранятся 30 минут (чтобы потом, например, «положи этот файл в задачу»).

## 5. Что ассистент умеет отправлять (инструменты `tg_*` бота)

Инструменты шлют в чат **сразу**, до финального ответа модели. После них финальный ответ — короткий, без пересказа отправленного. Список отправленного добавляется в историю служебной пометкой, чтобы модель «помнила», что уже отправила.

| Инструмент | Что делает |
|---|---|
| `tg_send_checklist` | интерактивный список с кнопками-галочками (до 60 пунктов). Нажал — пункт отмечен, сообщение перерисовывается; есть кнопка «🗑 Убрать отмеченные» |
| `tg_update_checklist` | добавить / убрать / отметить / снять / переименовать (пункты ищутся по тексту: точно, иначе по подстроке) |
| `tg_get_checklists` | текущее состояние списков чата («что ещё не куплено?») |
| `tg_send_file` | отправить файл. Собирает **DOCX, XLSX, PPTX, PDF** из markdown-разметки/таблиц; txt/md/csv/json/html/код — как есть; готовый бинарник — `content_base64`; файл/картинка по ссылке — `url`. Типы: document, photo, video, audio, voice, animation. Подпись — HTML до 1024 символов. До 45 МБ. CSV пишется с BOM, чтобы Excel не ломал кириллицу |
| `tg_generate_image` | рисует картинку по описанию (OpenAI), sizes: square / landscape / portrait; пока рисует — анимированное «сообщение о прогрессе» (бегущая луна, полоска, секундомер, этапы), которое потом удаляется |
| `tg_send_poll` | опрос 2–10 вариантов; режим викторины (правильный вариант + пояснение) |
| `tg_send_buttons` | сообщение с кнопками: либо `url`, либо `reply` (текст, который вернётся ассистенту при нажатии). До 8 рядов × 4 кнопки |
| `tg_send_location` | геопозиция, с `title` — как место с адресом |
| `tg_send_contact` | карточка контакта |
| `tg_send_dice` | кубик/дартс/баскетбол/футбол/боулинг/автомат — жребий, «орёл или решка» |
| `tg_react` | реакция-эмодзи на сообщение пользователя |
| `tg_pin_message` | закрепить/открепить (по умолчанию — последнее отправленное в этом ответе) |

### Синтаксис документов для `tg_send_file`
Заголовки `#`, списки `-` и `1.`, таблицы `|a|b|`, `**жирный**`, `*курсив*`, `` `код` ``, блоки ``` ``` ```, цитаты `>`, разделитель `---`. В PPTX новый слайд начинается на `#`/`##` или `---`. В XLSX — `sheets: [{name, rows:[[…]]}]`, первая строка — шапка, ячейка с `=` — формула.

### Правила поведения (зашиты в системный промпт)
- Список покупок/дел/сборов/шагов — **всегда** чеклистом, а не текстом.
- Длинный текст/таблица/код/выгрузка (> ~25 строк) — **файлом**, а не простынёй.
- Просят «Word / Excel / презентацию / PDF» — именно этот формат, не txt.
- «Нарисуй…» — генерирует сама, а не предлагает промпты для сторонних сервисов.
- Выбор из вариантов — кнопки; голосование — опрос.

## 6. Форматирование ответов

Ответ уходит в Telegram как **HTML**. Модель инструктируется писать теги (`<b> <i> <u> <s> <code> <pre> <a href> <blockquote> <blockquote expandable> <tg-spoiler>`), а не markdown.

Что делает сервер (`to_tg_html`, `split_html`, `send_text`):
- whitelist тегов Telegram, всё остальное экранируется; `< > &` в обычном тексте безопасны;
- **страховка:** если модель всё-таки написала markdown (`**жирный**`, `# заголовок`, `` `код` ``, ```` ``` ````, `- список`, `[текст](url)`) — превращается в HTML;
- **нарезка** длинных ответов (кусок ≈ 3500 символов сырого HTML) без разрыва тегов: открытые теги закрываются в конце части и переоткрываются в следующей; HTML-сущности не рвутся. Пользователь видит ответ целиком;
- если Telegram отклонил разметку («can't parse entities») — отправка повторяется простым текстом;
- превью ссылок отключено; поддерживаются «тихая» отправка и reply на сообщение.

Стиль (из промпта): ключевое — жирным, второстепенное — курсивом; блоки с заголовками-эмодзи; перечни строками `• `; числа/коды/команды в `<code>`; таблицы в `<pre>`; длинная справка в сворачиваемой цитате; эмодзи умеренно; короткий ответ — просто текст.

## 7. Память диалога

- **Хранится в памяти процесса** (после рестарта чат начинается заново). Только чистый текст ролей `user`/`assistant` — служебные ходы tool-use в историю не попадают (иначе смена провайдера Claude↔OpenAI посреди переписки ломала бы формат).
- **TTL 10 минут** (`ASSISTANT_CONTEXT_MINUTES`): пауза дольше — контекст сбрасывается, начинается новый диалог. Команда `/new` (или `/reset`) — сброс вручную.
- Максимум **30 сообщений** истории; история всегда начинается с сообщения пользователя.
- **Название диалога.** Первое сообщение нового диалога → LLM придумывает короткое название (2–5 слов) параллельно с основным ответом; при ошибке — начало сообщения. Под каждым ответом подпись: `💬 Диалог: «название» · сообщений: N`. У первого ответа нового диалога: `🆕 Новый диалог: «…»` + пояснение, почему закрыт прошлый (пауза или `/new`).
- **Якоря.** Отчёты, которые бот присылает сам (например, сбор информации по задаче), сохраняют контекст по `chat_id:message_id` (до 80 штук, на диске). Если пользователь ответит на такое сообщение (Reply) даже через несколько часов — диалог восстановится вместе с отчётом, подпись «↩ Продолжаем диалог».
- Сообщения чата обрабатываются под блокировкой — гонок в истории нет.

## 8. LLM-цикл (tool use)

Один и тот же набор инструментов, два адаптера:

- `_assistant_loop_claude` — Anthropic Messages API (`tools`, `tool_use` / `tool_result`);
- `_assistant_loop_openai` — Chat Completions (`tools` типа function, `tool_calls`, сообщения `role: tool`).

Параметры: `max_tokens` 8192, таймаут запроса 60 с, **до 8 шагов + 4 запаса** (не уложилась — «Не разобрался за отведённое число шагов, переформулируйте»). Если ответ оборвался по лимиту токенов — до 4 раз автоматически просит «продолжи без повторов» и склеивает.

Особенности:
- Ошибки инструментов возвращаются модели как `{"error": …}` — она сама объясняет пользователю.
- Инструмент может вернуть **картинку** (`_image`) — модель её увидит (Claude: image-блок в tool_result; OpenAI: отдельным сообщением после tool-ответов).
- Режим «фоновый агент только на чтение» (`allowed` — белый список инструментов): используется для отчётов по расписанию.
- Системный промпт собирается динамически (`build_assistant_system_prompt`): секция форматирования и возможностей Telegram, **сегодняшняя дата и день недели** (считает сервер — модели плохо считают день недели сами), факты о пользователе из раздела «База данных» (до 6000 символов, закреплённые первыми), описание инструментов, правила подтверждения, секции только включённых навыков.

## 9. Инструменты по работе с данными проекта (специфично для Джарвиса)

Эту часть в другом проекте заменяете своей предметной областью, но **схема переносится**:

- `get_data(domain)` — прочитать раздел данных (дом/задачи, авто, здоровье, бюджет, питание, учёба, события и т. д.). Правило промпта: не отвечать «по памяти» о данных пользователя — сначала `get_data`.
- `navigate(target)` — дать ссылку на раздел сайта (в конце ответа добавляется «Открыть: …»).
- `create_record / update_record / delete_record(collection, …)` — универсальная запись через реестр `WRITE_REGISTRY` (у каждой коллекции — подпись, дефолты, каскадное удаление, флаг подтверждения).
- Канбан: `kanban_create/update/delete/move_task`, комментарии, подзадачи.
- Отметки по дням: `log_diet_compliance`, `log_checklist_answer`.
- План готовки: `cooking_plan_add/update/delete_ingredient`.
- `get_weather(city?, date?, date_from?, date_to?)` — Open-Meteo, текущая погода + 3 дня, прогноз до 16 дней; город по умолчанию из настроек.
- `study_schedule` — расписание пар (rasp.rea.ru); `study_attach_file` / `study_get_attachment` — положить созданный/присланный файл в задание «Учёбы» или прочитать/прислать вложение.
- Apple Календарь и Напоминания (iCloud): `calendar_*`, `reminders_*`. Чтение свободно; любая запись — только после явного согласия.

### Механизм подтверждения (переносится целиком)
Опасное/необратимое (удаление, финансовые записи, отправка от имени пользователя) требует `confirmed:true`. Без него инструмент **ничего не делает** и возвращает `{"needs_confirmation": true, "message": …}`. Модель обязана:
1. описать простыми словами, что собирается сделать;
2. спросить подтверждение **финальным ответом** (не вызывая инструмент повторно);
3. вызвать тот же инструмент с `confirmed:true` только после «да» **следующим** сообщением пользователя.

## 10. Файлы: чтение и создание (`file_tools.py`)

- **Чтение** `read_file(data, name, limit)` → текст: docx (абзацы + таблицы по порядку), xlsx/xls (листы), pptx (текст слайдов), pdf (текстовый слой), rtf, odt/ods/odp, zip (список + содержимое), текстовые форматы. Тяжёлые библиотеки импортируются лениво — без них сервер живёт, а нужный формат отвечает понятной ошибкой.
- **Создание** `build(filename, content|sheets)` из лёгкой markdown-разметки: DOCX (заголовки, списки, таблицы с заливкой шапки, жирный/курсив/код), XLSX (листы, формулы), PPTX (слайды по заголовкам), PDF (кириллица, шрифты в `assets/fonts`).

## 11. Навык «Презентации» (`deck_skill.py`, `deck_builder.py`)

Ассистент работает как дизайнер презентаций:
- уточняет **одним сообщением** (≤ 3 вопроса): аудитория, длительность, цель/тон, язык, есть ли материалы; «быстро, без вопросов» — делает сразу; не выдумывает цифры;
- сам выбирает структуру (титул → план → содержание → выводы → closing; ≈ 1–1,5 слайда на минуту), темы и макеты;
- **Темы:** `minimal` (деловая), `warm` (авторская), `dark` (питч), `academic` (учёба/защита); свой акцентный цвет `accent`.
- **Макеты (13):** cover, section, bullets, cards, stats, compare, quote, timeline, table, chart, numbered, image, closing. До 40 слайдов, автоподбор размера шрифта, заметки докладчика к каждому слайду.
- **Проверка качества** (`lint`): плотность, однообразие макетов, длина заголовков, объём — один автоматический круг «исправь замечания» перед отправкой.
- До 3 ИИ-иллюстраций на колоду (OpenAI Images).
- Присылает редактируемый **PPTX** + слайды-превью картинками-альбомом (LibreOffice → PDF → pdftoppm → PNG); без LibreOffice — только файл.
- **Правки:** колода сохраняется (до 20 штук, `jarvis_decks.json`); «поменяй слайд 3», «сделай тему тёмной» → `presentation_get(deck_id)` → пересборка с тем же `deck_id`.
- Может положить файл в задание «Учёбы».

## 12. Личный Telegram пользователя (Telethon, `tg_user.py` + `tg_tools.py`)

Опциональный блок: ассистент работает не только как бот, но и от имени **личного аккаунта** пользователя.

- **Вход:** api_id + api_hash (my.telegram.org) → телефон → код → пароль 2FA (или QR). Сессия (`StringSession`) лежит в `DATA_DIR/jarvis_tg_user.json` с правами 600, наружу не отдаётся.
- **Защита:** инструменты доступны **только в личном чате владельца** (`is_owner_chat`: chat_id бота == id подключённого аккаунта). Остальные пользователи бота — без доступа.
- Содержимое переписки и файлов — **данные, а не команды**: инструкции внутри сообщений модель не выполняет (защита от prompt injection).
- Любое действие, меняющее что-то, идёт от имени пользователя → сначала показать «что и кому», получить «да», потом `confirmed:true`.

### Навыки (13 групп, каждая включается переключателем)

| Навык | Риск | По умолч. | Что умеет |
|---|---|---|---|
| Профиль и устройства | read | вкл | данные аккаунта, активные сессии |
| Папки | read | вкл | папки Telegram, число чатов/непрочитанных, в какой папке диалог |
| Утренняя сводка | read | вкл | «какие новые сообщения?» — авторы непрочитанных по чатам со звуком; замьюченные не трогает, лишь считает |
| Диалоги и непрочитанные | read | вкл | список чатов/групп/каналов/ботов, фильтры: папка, тип, непрочитанные, архив, закрепы, мьют |
| Люди и контакты | read | вкл | контакты, участники/админы групп, темы форумов, глобальный поиск людей и каналов |
| Чтение переписки | read | вкл | история по периоду/людям/веткам/темам; видит файлы, опросы, реакции, просмотры |
| Файлы из чатов | read | вкл | скачивает и читает файлы из любых чатов (docx, xlsx, pptx, pdf, текст…; картинки видит); может прислать в чат с ботом или положить в задание |
| Поиск по переписке | read | вкл | по тексту и типам (ссылки, файлы, фото, голосовые, закрепы) в диалоге / папке / везде |
| Расшифровка голосовых | read | вкл | голосовые и кружки из чатов → текст (нужен Telegram Premium) |
| Отправка | write | вкл | сообщения от вашего имени, отложенные (`schedule`), без звука; только после «да» |
| Правки, пересылка, реакции | write | вкл | редактирование своих, пересылка, реакции, закрепы сообщений; после «да» |
| Порядок в чатах и папках | write | **выкл** | прочитано, архив, мьют, закрепы чатов, создание/изменение папок |
| Опасные действия | danger | **выкл** | удаление сообщений, вступление/выход из чатов, блокировка |

Правила промпта для сводки: на «что нового / кто писал / что непрочитано» **сначала** `tg_unread_digest`, читать только чаты со звуком; замьюченные читать, только если пользователь сам их назвал.

Пример сложной задачи, которую решает: «в группе скинули файл со списком тем, все отвечают, какую берут — скажи свободные» → найти сообщение с файлом → `tg_get_file` → `tg_get_replies` → сопоставить (последнее слово человека главнее; неясное помечать «неясно») → вывести занятые и свободные.

## 13. Навыки «Учёбы» (фоновые отчёты)

- **Сбор информации по задаче** (`study_brief`): кнопка в карточке задания (или просьба в чате). Фоновый агент **только на чтение** смотрит описание, шаги, комментарии, вложения, расписание, ищет упоминания в учебных чатах и присылает в бот отчёт: саммари, источники, чего не хватает, план. Ответ на отчёт продолжает диалог с его контекстом (якорь).
- **Контроль учебных чатов** (`study_chats`): раз в день читает выбранные чаты (даже замьюченные) и пишет в бот **только если** есть что-то важное: вопросы вам/всем, упоминания, «ищут вас», новые задания, переносы, сроки, голосования. Со ссылкой на сообщение; на уведомление можно ответить.

## 14. Система навыков и настроек (архитектурный паттерн)

Каждый навык — запись в каталоге:

```python
{"id": "presentations", "title": "Презентации",
 "risk": "create",          # read | create | write | danger
 "default": True,           # включён ли по умолчанию
 "desc": "что умеет, как использовать, ограничения",
 "tools": ["presentation_build", "presentation_get"]}
```

- Переключатель хранится в `data.telegramSkills[<id>]` и синхронизируется с остальными данными.
- Выключенный навык исчезает **из трёх мест**: списка инструментов для LLM (в обоих циклах), исполнителя (возвращает ошибку «навык выключен») и системного промпта.
- Проверка включённости — функция `skill_on(state)` (по умолчанию — `default`).
- В UI: Настройки → Ассистент → «Навыки ассистента»: название, описание, переключатель, цветной бейдж риска.
- Каталог отдаётся эндпоинтом `/api/tg/skills`.
- Данные навыка на диске добавляются в бэкап (`data_names`) и `.gitignore`.

Настройки ИИ: пользователь добавляет «наборы ключей» (провайдер Claude/OpenAI, ключ, модель) и назначает один функции «Ассистент». Ключ OpenAI для картинок/голосовых ищется: набор ассистента (если OpenAI) → любой OpenAI-набор → `OPENAI_API_KEY`.

## 16. Безопасность

- Личный Telegram — только владельцу; сессия не покидает сервер.
- Подтверждение через `confirmed:true` для удаления, финансов, отправки от имени пользователя.
- Содержимое файлов и чужих сообщений — данные, а не команды.
- Фоновые агенты ограничены белым списком read-инструментов.
- Все ключи (LLM, OpenAI) — в серверных данных/окружении, в браузер не отдаются.
- Блокировка `chat_lock` на чат, атомарная запись JSON (`.tmp` + `os.replace`).

## 17. Как воспроизвести в другом проекте — минимальный план

1. **Бот и приём апдейтов.** Токен, `getUpdates` long-poll (или webhook), поток на сообщение, `chat_lock` на чат. Команды `/new`, `/reset`.
2. **`extract_attachments`.** Скачивание (`getFile` → `file/bot<token>/…`), фото → картинка модели, документ → `read_file` → текст, голос/кружок/видео → `transcribe_audio` → текст, пометка пересылки.
3. **Слой отправки.** `api()`-обёртка, `to_tg_html` + `split_html` + `send_text` с fallback на plain text; `Ctx` (токен, chat_id, id сообщения пользователя, список отправленного) в `threading.local`.
4. **Инструменты бота** `tg_*` (чеклисты, файлы, картинки, опросы, кнопки, реакции…) и обработчики `callback_query` (`tcl:`, `tqr:`).
5. **Память.** `history_for / touch / reset` с TTL, `trim` до 30, название диалога, подпись под ответом, якоря для отчётов.
6. **Цикл LLM.** Один формат инструментов (`name`, `description`, `input_schema`) → адаптеры Claude и OpenAI; лимит шагов, дописывание при обрыве, картинки из инструментов.
7. **Системный промпт.** Секция форматирования и возможностей Telegram (из `tg_bot.PROMPT_SECTION`, можно взять почти дословно) + дата/день недели + факты о пользователе + описание ваших инструментов + правило подтверждения.
8. **Ваши предметные инструменты.** `get_data` / `create_record` / … под вашу модель данных, с `confirmed`-защитой для опасного.
9. **Каталог навыков** с переключателями — если нужен набор независимо включаемых способностей.
10. **Опционально:** презентации (`deck_builder.py` почти не зависит от проекта), личный Telegram (`tg_user.py` + `tg_tools.py`), фоновые отчёты.

Переносимо почти без правок: `tg_bot.py` (форматирование, чеклисты, кнопки, файлы, опросы, память, вложения), `file_tools.py`, `deck_builder.py`, `tg_user.py`, `tg_tools.py`. Привязано к Джарвису: `jarvis.py` (инструменты данных, настройки, подписчики, напоминания), `study_*`.

### Скелет основного цикла (псевдокод)

```python
def handle(token, chat_id, text, images, msg_id):
    with chat_lock(chat_id):
        history = history_for(chat_id)               # сброс по TTL
        touch(chat_id)
        turn = history + [user_message(text, images)]
        set_ctx(Ctx(token, chat_id, msg_id))
        try:
            answer = llm_loop(turn, tools=enabled_tools(), system=build_system_prompt())
        finally:
            set_ctx(None)
        history += [{"role": "user", "content": text},
                    {"role": "assistant", "content": answer + sent_note}]
        trim(history)
        send_text(token, chat_id, answer + dialog_footer(chat_id))

def llm_loop(convo, tools, system):
    for _ in range(MAX_STEPS + 4):
        resp = call_llm(system, convo, tools)
        if not resp.tool_calls:
            return resp.text
        for call in resp.tool_calls:
            result = execute_tool(call.name, call.input)   # ошибки -> {"error": ...}
            convo.append(tool_result(call.id, result))
    return None   # "не разобрался за отведённое число шагов"
```
