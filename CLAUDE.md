# Джарвис — заметки для Claude

Личное приложение: сайт-SPA (`index (9).html`) и сервер (`jarvis.py`) с Telegram-ботом, ассистентом и напоминаниями.
Деплой — Railway из ветки `main`; данные лежат в `DATA_DIR` (Volume). Отвечать пользователю по-русски, коротко.

## Новый навык ассистента — ВСЕГДА регистрировать в настройках

Любой новый навык Джарвиса (то, что умеет ассистент в боте, чате или голосом) должен появляться в списке
**Прочее → Настройки → Ассистент → «Навыки ассистента»**: с названием, описанием и переключателем.
Тот же список (компонент `AssistantSkillsCard`) показан и во вкладке «Телеграм». Без записи в этом каталоге навык считается не сделанным.

Что нужно сделать:

1. **Запись в каталоге** — словарь `{"id", "title", "risk", "default", "desc", "tools": [имена инструментов]}`:
   - `risk` — `read` (чтение), `create` (создаёт файлы), `write` (действия с подтверждением), `danger` (опасно);
     подписи и цвета бейджей — `riskLabel` / `riskCls` в `AssistantSkillsCard` (`index (9).html`); новый тип риска добавлять туда же;
   - `default` — включён ли по умолчанию; `desc` — по-человечески: что умеет, как использовать, ограничения
     (например, «превью требует LibreOffice на сервере»).
2. **Где хранить запись:**
   - навыки личного Telegram (Telethon) — в `TG_SKILLS` в `tg_tools.py` (там же проверка, что все `tools` существуют);
   - остальные — в своём модуле списком `SKILLS` (образец — `deck_skill.py`) и добавить его в выдачу `/api/tg/skills`
     в `jarvis.py` (`deck_skill.SKILLS + tg_tools.skills_catalog()`).
3. **Переключатель** хранится в `data.telegramSkills[<id>]` (синхронизируется как обычные данные). Выключенный навык
   не должен попадать ни в список инструментов ИИ (оба цикла `_assistant_loop_claude` / `_assistant_loop_openai`),
   ни в исполнитель (`execute_assistant_tool`), ни в системный промпт (`build_assistant_system_prompt`).
   Проверка включённости — функция `skill_on(state)` в модуле навыка (по умолчанию — `default`).
4. **Данные навыка** на диске — добавить файл в `data_names` (бэкап в `jarvis.py`) и в `.gitignore`.
5. **Проверить:** навык виден в списке и переключается; при выключении инструменты исчезают из запроса к ИИ;
   сквозной тест с подменой ответов модели и Telegram API.

## Карта проекта

- `jarvis.py` — HTTP-сервер, минутный цикл напоминаний (`_tick`), ассистент (инструменты, циклы Claude/OpenAI),
  «Учёба» (расписание rasp.rea.ru, вложения заданий, напоминания по заданиям), бэкапы.
- `tg_bot.py` — возможности бота: форматирование (HTML Telegram), чеклисты, файлы, опросы, картинки, расшифровка
  голосовых, память диалога (TTL 10 мин, название диалога под ответом), входящие вложения.
- `widget_skill.py` — навык `telegram_widgets` (по умолчанию включён): `tg_send_widget` отправляет
  самодостаточный HTML/CSS/JS через Bot API `sendWidget` в текущий личный чат. Выбор по просьбе или
  самостоятельно; группа `widgets` всегда доступна, чтобы формат не зависел от темы запроса.
  Локальная интерактивность без запросов боту и серверных действий; лимиты UTF-8/zlib-9 проверяются
  до отправки. Подпись сохраняется обычным архивом бота. Тесты — `test_widgets.py`.
- `tg_history.py` — навык `bot_history` (включён по умолчанию): постоянный архив текущего чата с ботом,
  поиск и чтение через `tg_bot_history`, восстановление обсуждения по любому ответу на сообщение.
  Хранилище — `DATA_DIR/jarvis_tg_history.sqlite3` (SQLite, 600, снимок в бэкапе). Пауза и /new закрывают
  рабочий контекст, сохраняя архив. Архивируются входящие тексты/расшифровки и отправленные сообщения/подписи;
  бинарные вложения и токены не сохраняются. Переписка до включения навыка доступна через Telethon только
  владельцу и только с текущим ботом (peer определяется через getMe). Bot API и MTProto имеют разные id:
  не объединять их по числу, для старого reply сопоставлять точный текст и время. Тесты — `test_bot_history.py`.
- `tg_tools.py` / `tg_user.py` — личный Telegram пользователя (Telethon): чтение, поиск, файлы, ответы, отправка.
  Темы форумов (навык `topics`): список, создание/правка, чтение и отправка в тему, перенос сообщений между темами/группами
  фоновой задачей (`tg_topic_copy`: copy/forward, период, тип; итог в бот через `tg_tools.job_notify`). Тесты — `test_tg_topics.py`.
- `file_tools.py` — чтение и создание docx/xlsx/pptx/pdf и др.; шрифты для PDF — `assets/fonts`.
- `study_skills.py` — навыки «Учёбы»: «Сбор информации по задаче» (кнопка в карточке задачи, фоновый агент только на чтение,
  отчёт в бот) и «Контроль учебных чатов» (ежедневная проверка, настройки в `data.studyChats`); запуск и рассылка — в `jarvis.py`
  (`start_study_brief`, `study_chats_scan`). Отчёты бота хранят контекст: `tg_bot.remember_anchor` / `restore_anchor`
  (ответ на сообщение бота возвращает диалог и после паузы).
- `mail_skill.py` — навык «Почта Mail.ru» (только чтение): ящики по IMAP (Настройки → Почта), индекс заголовков всех папок
 (у Mail.ru IMAP SEARCH не ищет по тексту), инструменты `mail_*`, фоновая проверка раз в 90 с без IDLE; уведомления —
 общая маршрутизация, категория `mail:<id ящика>`. Пароли приложений — `DATA_DIR/jarvis_mail/` (600, не в бэкапе). Тесты — `test_mail.py`.
 Фоновая проверка: каждый ящик в своём потоке с дедлайном, уведомления не блокируют цикл, сторож (`ensure_poller` из минутного
 цикла и `/api/mail/status`) поднимает умерший или зависший поток; в логе — `mail: poller started…` и строка на каждый ящик.
- `plan_skill.py` — навык «Планирование и напоминания»: ассистент сам ставит плановые задачи (`plan_create/list/update/cancel`):
 `remind` — текст в бот в срок; `task` — поручение, которое ассистент выполняет сам (отчёт в чат — только если пользователь так ответил;
 `report` обязателен, ошибку сообщаем всегда). Запуск — `_plan_tick` в минутном цикле (`claim_due` → `_plan_worker` в `jarvis.py`);
 при выполнении без пользователя `confirmed` отрезается в `execute_assistant_tool` (`_plan_scope`), новые задачи ставить нельзя.
 Хранилище — `DATA_DIR/jarvis_plan_tasks.json`; API `/api/plan/*`; список со статусом и результатом — Настройки → Ассистент → «Плановые задачи».
 Тесты — `test_plan.py`.
- `newspaper.py` — утренняя газета A4: берёт сегодняшние дела «Босса», Apple Calendar, погоду, 4 мировые новости,
  цитату и факт; делает крупное монохромное PDF и PNG-превью. Настройки и превью — Настройки → Газета (`data.newspaper`),
  ручная сборка — `POST /api/newspaper/generate`, готовый файл — `/api/newspaper/today.pdf`, расписание запускает `newspaper_tick`
  в минутном цикле. Android-агент забирает очередь через `/api/tablet/newspaper/job`, находит IPP-принтер по mDNS и печатает
  PDF/PCLm/PWG Raster без системного диалога; отчёт — `/api/tablet/newspaper/report`. Кэш и последний выпуск —
  `DATA_DIR/jarvis_newspaper_*`. Тесты — `test_newspaper.py`, HTTP-поток — `test_tablet.py`.
- `ai_usage.py` — модели ИИ по ролям (main / complex / background + задачи studyBrief, triage, title, notesTargets), каталог цен и
 поддерживаемых уровней рассуждений, журнал расхода `jarvis_ai_usage.jsonl` (в бэкапе) и `jarvis_ai_turns.jsonl` (14 дней, не в бэкапе).
 Настройки — `data.settings.aiModels` (Прочее → Настройки → Ассистент: блоки «Модели по ролям», «Рассуждения», «Эскалация», «Группы инструментов»,
 «Кэш и промпт», «Расход ИИ»; компонент `AiCostBlocks`). Уровень рассуждений нигде не зашит в код — только из настроек. «Нейросети и ключи» — только API-ключи по провайдерам (поля «Модель» нет); провайдер и модель выбираются для каждой роли в «Модели по ролям»
 (провайдер выводится из имени модели: `claude-*` — Claude, иначе OpenAI; нет ключа нужного провайдера — берётся другой с моделью по умолчанию).
 Эскалация — только внутри одного провайдера. `enabled:false` — прежнее поведение (модель из набора). API: `/api/ai/models`, `/api/ai/usage`. Тесты — `test_ai_models.py`.
- `tool_groups.py` — группы инструментов по смыслу запроса (переключатель `aiModels.toolGroups`, по умолчанию выключен = полный набор) и
 `tools_more`. **Новый навык/инструмент — ВСЕГДА добавлять в группу `GROUPS` (и ключевые слова `KEYWORDS`)**, иначе он считается «без группы»
 и остаётся всегда включённым. Группы работают поверх `skill_on`: выключенный навык не возвращается.
 OpenAI: инструменты вместе с рассуждениями Chat Completions не принимает — при уровне ≠ none цикл идёт через Responses API (`_openai_step`, `_responses_call`; в браузере — `openaiVoiceStep`).
 Эскалация на «сложную» модель — `_TurnState.escalate` / `_needs_complex` в `jarvis.py`; промпт для кэша — `build_assistant_system_prompt(split=True)`.
- `deck_builder.py` / `deck_skill.py` — навык «Презентации»: движок слайдов (темы, макеты, проверка качества) и интеграция.
- `android/tablet-voice/` — sideload APK «как Алиса» на планшете (Galaxy Tab A9): foreground service микрофона, wake word «Джарвис», STT, TTS с перебиванием, автозапуск и независимый WorkManager-агент утренней печати по IPP. Мозг — `POST /api/tablet/turn` (тот же `_assistant_loop_*`, cookie или токен устройства). Инструкция — `android/tablet-voice/README-sideload.md`.
- `index (9).html` — всё приложение одним файлом (React через Babel в браузере); раздел «Учёба» — `StudyView`.
  Настройки → Ассистент (`VoiceAssistantSettings`) разбит на сворачиваемые блоки `AssistantBlock` (по умолчанию закрыты):
  «Плановые задачи» (`PlannedTasksBlock`), навыки, ключи ИИ, Apple, голос и ссылки, инструкция. Новый блок — тоже через `AssistantBlock`.
  «Прочее» (`MiscView`) — плашки с названиями; карандаш включает свободное перетаскивание: позиции в `data.miscChipPos[compact|wide]`
  (x — доля ширины, y — px; отдельно для телефона и ПК; пусто — плашки идут подряд по `miscAppsOrder`); «Сбросить» возвращает поток.
  «Бюджет» на телефоне (уже 768px, хук `useBudgetMobile`) — карточки вместо таблиц, редкие действия в `BudgetActionSheet` («⋯»),
  быстрые отметки с тостом «Отменить» (`useBudgetUndo`); все `Modal` внутри `BudgetView` на телефоне — шторки снизу
  (`ModalSheetContext`). ПК-вёрстку раздела мобильные правки не меняют.
- «Прочее → Заметки» (`NotesView`, адрес `/notes`) — блокнот из разделов `NOTES_SECTIONS` (новый раздел — запись туда со своим `View`).
 Пока раздел «Сим-карты» (`SimCardsView`, CSS `sim-*`): данные — id-массивы `simCards` / `simDevices` (обычная синхронизация);
 виды карточки/список/по устройствам/платежи. Ассистенту — домен `sims` (без PIN/PUK и паролей) и запись через `WRITE_REGISTRY`.
- `requirements.txt` — зависимости ставит Railway при деплое; новые библиотеки добавлять сюда.
- `market_pc.py` / `windows/wb-extension/` — WB через Chrome на Windows: исходящие poll/result,
  ключ устройства даёт доступ только к двум этим маршрутам. В настройках маркетплейсов — ZIP, ключ,
  статус ПК и проверка чтения. `jarvis_market_pc.json` хранит только хэш ключа; задания в памяти.
  При подключённом ПК инструменты WB читают покупки/доставки без серверного прокси; остальные действия
  явно недоступны. Cookies и коды остаются в Chrome. Тесты — `test_market_pc.py` и `tests/wb_extension.test.cjs`.
  В расширении «Поля товаров и ПВЗ» — локальный каталог полученных полей с примерами и выбором дополнительных
  полей для Джарвиса. `field-utils.js` исключает секреты; весь каталог не отправляется серверу. EB-позиции
  связываются с артикулом по order id и индексу, статусы — по активному rid; цены карточки не подменяют цену заказа.
  `item.price` для RUB подтверждён в копейках. По умолчанию ответ WB — название, цена, статус;
  дополнительные поля возвращаются только при `details:true` в market_orders/market_delivery по прямому запросу.
- `wb_watch_skill.py` — фоновый навык `wb_pickup` (включён по умолчанию): проверяет доставки WB через ПК каждый час,
  в 10:00 МСК сообщает только о готовых к выдаче позициях (название, цена, статус) в личный чат владельца с ботом.
  Готовность после утреннего окна — следующим утром; повтор через три дня, только при свежем подтверждении готовности.
  Минутный цикл запускает отдельный поток: чтение ПК не блокирует напоминания. Ошибки и отсутствующие позиции
  не считаются сменой статуса. История уведомлений — `DATA_DIR/jarvis_wb_pickup.json`, входит в бэкап.
  Выключение `wb_pickup` или `marketplaces` останавливает проверку и отправку; тесты — `test_wb_watch.py`.
- Ozon через тот же ключ/очередь ПК: расширение 0.3.0 объявляет `capabilities:["wb","ozon"]`; старый клиент
  остаётся WB-only и не получает задания Ozon. В заданиях Ozon есть `shop:"ozon"`; сессии магазинов независимы.
  `windows/wb-extension/ozon-capture.js` читает buyer widgets `orderList.ordersV2` и `shipmentWidget` из DOM/ответов,
  а названия/цены — из фиксированного GET `/my/orderdetails/?order=...` (до 40 заказов, 3 параллельно, общий бюджет 18 с,
  продолжение с оставшихся в следующем проходе). Артикул/статус связываются по заказу, посылке и SKU,
  не по порядку карточек и не по bundle-ссылке группы. Ozon price — готовая денежная подпись, числа без валюты не конвертировать.
  Завершённые заказы — `/my/orderlist?selectedTab=archive`, только загруженная часть; всегда `truncated:true`.
  Каталоги полей, выбор и логи Ozon/WB разделены. `ozon_pickup` в `wb_watch_skill.py` включён по умолчанию, работает
  по тому же расписанию, но уведомляет только по стабильным `ozon:<order>:<shipment>:<sku>`. История —
  `jarvis_ozon_pickup.json` (в бэкапе). Тесты — `test_ozon_pc.py`, `tests/ozon_extension.test.cjs`, `tests/test_ozon_browser.py`.
  Адаптер проверен на синтетических buyer widgets; реальные поля кабинета подтверждаются через диагностику расширения.
- `nixpacks.toml` — системные пакеты для сборки на Railway (`aptPkgs`): LibreOffice и poppler для превью презентаций;
  нужен новый системный пакет — добавлять сюда.

## Как проверять

- Серверную логику и ассистента — скриптами с подменой `requests.post` и `tg_bot.api` (без настоящих Telegram/ИИ).
- Интерфейс — локальным запуском `python jarvis.py --port 8765` с временным `DATA_DIR` и браузером (Playwright);
  вход на сайт — cookie `jarvis_auth`. CDN-скрипты (React, Babel, Tailwind) из песочницы недоступны — подменять локальными.
- Пуш в `main` — только по явной просьбе пользователя.
